# Проверка проекта

Этот документ содержит обязательный sanity-check для любой фичи, которая меняет видимое поведение сайта. Он дополняет автоматические проверки и критерии приёмки конкретной фичи, но не заменяет их.

## Как проводить проверку

На контрольной точке владельца проверки выполняются в следующем порядке:

1. Пройти sanity-check из этого документа.
2. Выполнить конкретные сценарии из `docs/features/<feature-name>/VERIFICATION.md`.

При каждом `CHECKPOINT` или другом запросе на ручную проверку агент прикладывает кликабельную ссылку на этот файл. Если у текущей фичи есть собственный `VERIFICATION.md`, агент также прикладывает ссылку на него.

Обнаруженные проблемы записываются в файл проверки соответствующей фичи. После исправления нужно повторить сценарий, в котором была найдена проблема, и связанные с ним пункты sanity-check.

## 1. Общее

Эти пункты нужно проверить и на компьютере, и на реальном телефоне.

- [ ] Страница открывается без пустого экрана, видимой ошибки или бесконечной загрузки.
- [ ] На странице присутствуют шапка, основной контент, галерея, контактный раздел и подвал.
- [ ] Текст отображается на иврите, читается корректно и сохраняет направление справа налево.
- [ ] Логотип и изображения загружаются; на странице нет явно сломанных изображений.
- [ ] Навигация в шапке приводит к нужным разделам страницы.
- [ ] Телефон, WhatsApp, Instagram и другие видимые контактные ссылки открывают ожидаемое приложение или страницу.
- [ ] Категории галереи переключаются и показывают соответствующие изображения.
- [ ] Кнопки «назад» и «вперёд» в галерее работают там, где они доступны.
- [ ] Нажатие на изображение открывает лайтбокс с выбранным изображением.
- [ ] В лайтбоксе можно перейти к предыдущему и следующему изображению и закрыть его видимыми элементами управления.
- [ ] После обновления страницы сайт остаётся доступным и работает так же.
- [ ] Во время проверки в консоли браузера не появляются новые ошибки.

## 2. Только веб

Эти пункты нужно проверить в браузере на компьютере.

- [ ] На обычной ширине экрана нет наложений, обрезанного контента и неожиданной горизонтальной прокрутки.
- [ ] При изменении ширины окна макет перестраивается без заметных поломок.
- [ ] Все интерактивные элементы доступны с клавиатуры с помощью `Tab` и `Shift+Tab`.
- [ ] У элемента в фокусе есть хорошо заметный индикатор.
- [ ] `Enter` и `Space` активируют кнопки и ссылки там, где это ожидается.
- [ ] Мобильное меню не отображается на ширине десктопа.
- [ ] Галереей можно управлять кнопками и перетаскиванием мышью.
- [ ] Лайтбокс можно закрыть кнопкой, нажатием на фон и клавишей `Escape`.
- [ ] Стрелки клавиатуры переключают изображения в открытом лайтбоксе.
- [ ] После закрытия меню или лайтбокса клавиатурный фокус возвращается к элементу, который его открыл.
- [ ] При увеличении страницы до 200% основной контент остаётся читаемым и доступным.

## 3. Только мобильная версия

Эти пункты нужно проверить на реальном телефоне в портретной и альбомной ориентации.

- [ ] Нет наложений, обрезанного контента и неожиданной горизонтальной прокрутки страницы.
- [ ] Мобильное меню открывается, все его действия работают, и меню можно закрыть.
- [ ] После выбора пункта мобильного меню происходит переход к нужному разделу.
- [ ] Все основные кнопки и ссылки удобно нажимаются пальцем и не перекрывают друг друга.
- [ ] Контактные действия открывают правильное приложение или системный экран.
- [ ] Галерея переключается кнопками и жестом горизонтального свайпа.
- [ ] Полноэкранный лайтбокс открывается с выбранным изображением.
- [ ] В лайтбоксе работает горизонтальный свайп между изображениями.
- [ ] Лайтбокс закрывается кнопкой и нажатием на фон, а страница под ним не прокручивается.
- [ ] После закрытия лайтбокса пользователь возвращается к тому же месту в галерее.
- [ ] После поворота телефона интерфейс остаётся читаемым, доступным и не ломается.
- [ ] При увеличенном системном размере текста важный текст и элементы управления не обрезаются.

## Проверка конкретной фичи

У каждой существенной пользовательской фичи должен быть файл `docs/features/<feature-name>/VERIFICATION.md`, содержащий:

- ветку-кандидат, дату и адреса для проверки;
- начальные условия, если важны устройство, размер экрана или состояние интерфейса;
- пронумерованные конкретные действия владельца;
- ожидаемый видимый результат каждого действия;
- связь сценария с требованиями или критериями приёмки;
- отдельный раздел с автоматическими и агентскими проверками;
- найденные проблемы, результаты повторных проверок и известные ограничения;
- итоговое решение владельца: принято или требуются изменения.

Сценарии должны описывать конкретные действия: «открыть», «нажать», «провести пальцем», «закрыть». Формулировки наподобие «проверить фичу» недостаточны.

## Обязательные технические проверки

Перед публикацией агент выполняет и записывает результаты:

```bash
npm ci
npm run typecheck
npm run build
npm audit --audit-level=high
git diff --check
```

В зависимости от требований и рисков фичи к ним добавляются проверки доступности, адаптивности, консоли браузера и отсутствия регрессий.
