# Идеи и планы проекта

## Назначение

Этот файл — единый список идей и возможных следующих направлений для Shir VaPerah Web. Запись идеи сюда не означает, что фича утверждена или готова к реализации.

Перед реализацией существенная фича должна пройти обычный процесс:

```text
идея -> требования -> дизайн -> задачи -> реализация -> проверка
```

Утверждённые требования и технические решения остаются в `docs/features/<feature-name>/`, `docs/project/REQUIREMENTS.md` и `docs/project/ARCHITECTURE.md`.

## Статусы

- **Идея:** предложение записано, но ещё не оценено и не утверждено.
- **Кандидат:** направление выбрано для следующего обсуждения; требования ещё не утверждены.
- **Запланировано:** требования и дизайн утверждены, дальнейшая работа ведётся в спецификации фичи.
- **Отложено:** возвращаемся только после отдельного решения владельца.
- **Завершено:** результат выпущен или идея закрыта без реализации; итог указан в примечании.

## Как вести файл

- Новую идею добавляем с постоянным ID, кратким результатом для пользователя и конкретным следующим шагом.
- Идеи не получают реализационные задачи до утверждения требований и дизайна.
- Изменение статуса сопровождаем датой и короткой причиной в журнале ниже.
- Если идея становится фичей, добавляем ссылку на её папку в `docs/features/`.
- Не удаляем закрытые идеи: переносим их в завершённые или отложенные, чтобы сохранить контекст решения.
- Не записываем сюда секреты, персональные данные и детали приватных систем.
